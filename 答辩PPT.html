一、问题与用户

用户是谁

正在写课程论文 / 毕业论文的大学生、研究生。他们懂研究，但不熟悉 GB/T 7714 著录规则。

痛点

  • 格式不统一：缺文献类型码、缺年份、标点混用
  • 漏引：正文引了列表没有，或列表有但正文没引
  • 文献真假难辨：引用了不存在或拼错的文献

一句话价值

把"找问题 → 核验 → 出报告"做成能规划、会用工具、能产出文件的 Agent，而不是单轮聊天框。

符合选题边界：学术诚信方向，只检查不代写

二、总体架构

用户 → Streamlit → Deep Agent →（模型 / 4 工具 / Skill+记忆 / 子代理）→ 产出报告到 workspace/；doi 工具联网访问 Crossref。

三、核心能力：4 个自定义工具（答辩重点）

工具作用关键技术点
parse_reference解析参考文献条目，统计漏引用正则切分 [n] 条目；扫描正文引用标记做覆盖率比对
check_citation_format对照 GB/T 7714-2015 查格式确定性规则：缺序号/类型码/年份、多作者未用"等"、标点混用、缺 DOI
search_paper_doiCrossref 核验文献真实性联网失败/超时优雅降级，不崩溃
generate_report写出校验报告 md+xlsx明确产出物，侧边栏可预览下载

为什么"工具"很关键

工具把事实来源固定到国标规则与 Crossref，模型只负责编排——避免凭记忆编造文献。调用过程在界面"执行过程"面板实时可见。

七、思政与合规说明

✅ 服务正当需求

属于推荐选题中的学术诚信方向：帮助学生规范引用，不涉及代写、作弊。

🔐 隐私与边界

不采集隐私；密钥仅在 .env（已被 .gitignore 忽略）；样例数据全部虚构。

使用边界提示

界面与报告均注明："本报告仅供修改参考，最终以学校/期刊规定与导师意见为准"，不对制度结论做情绪化断言。

八、演示步骤（推荐话术）

  1. 上传论文：侧边栏上传 examples/sample_paper.md → 点"用这篇论文开始检查"。
  2. 检查格式：看到 parse_reference + 多次 check_citation_format 被调用。
  3. 核验真实性：说"核验前 3 篇是否真实存在" → 看到 search_paper_doi 调 Crossref。
  4. 生成报告：说"生成校验报告并导出 Excel" → generate_report 写出 md+xlsx。
  5. 展示产出：侧边栏"产出文件"预览/下载《引用校验报告》。

详见仓库内 演示话术.md。断网时 doi 工具优雅降级，其余完全可离线演示。
